# Taste
- Communicates with the agent in Chinese (Simplified); reports bugs in natural-language, user-visible symptom terms rather than technical wording, and expects the agent to trace the root cause. Confidence: 0.8
- Prefers minimal, curated settings UI over exhaustive customization — explicitly pushes back on feature-rich config screens ("别提供那么多自定义选项"), wanting only the meaningful options exposed. Confidence: 0.7
- Points the agent at a concrete existing app/reference project to emulate its behavior and data sources, rather than describing the desired design abstractly. This is a recurring pattern, not a one-off: for later features they again hand over a repo link as the starting point (e.g., pointed at the `andelby/widbar` GitHub project to show how to embed into the taskbar). Confidence: 0.7
- Rejects fixes that trade one working behavior for another — a fix that resolves the reported bug but breaks existing functionality is treated as a failure. Expects the agent to keep hunting for a solution that satisfies both constraints (and to research the real mechanism when needed) rather than settling for a compromise. Confidence: 0.65
- Treats the user-visible symptom as the source of truth over the agent's own tests: if the artifact still visibly misbehaves, they re-report it tersely and emphatically ("还是会闪！现在是切换过程中闪！！！" / "切换过程还是闪白色！！！！！！" / "还是会被搞到下面去。。。。") and expect the agent to keep digging for the residual root cause instead of declaring victory off a passing test — even after the agent ran a self-constructed "decisive" experiment and called it verified. Confidence: 0.85
- Wants the definitive, root-cause fix rather than another incremental patch once an issue keeps recurring — explicitly asks for "一个完美方案" and grants permission to refactor ("必要的时候可以重构"). Do not offer band-aids or list of speculative options; if iterative fixes have failed, step back and fix the underlying mechanism. Confidence: 0.7
- Expects temporary diagnostic scaffolding (probe/verification scripts, temp instrumentation, throwaway build output) to be cleaned up once the fix is confirmed — explicitly asks for it ("可以清理探针") rather than leaving it in the tree. Confidence: 0.55
- Rejects having a bug attributed to their own environment/setup — when the agent hypothesizes the OS/settings are misconfigured, they push back emphatically ("我肯定没有禁用啊！") and expect the agent to own the root cause in the code instead of blaming the user's configuration. Confidence: 0.5
- Wants visual appearance to be user-switchable: expects a control (e.g., a setting) to toggle between looks rather than a single hardcoded style, while keeping the current look as the default/opt-in baseline (e.g., "目前是 Apple 风格，请你允许切换风格"). The minimal-settings preference applies to gratuitous customization, not to options directly tied to a feature they asked for — when offered sub-options for the requested feature they chose to expose both (Acrylic + Mica). Confidence: 0.5
- Expects hardcoded behavior to be turned into a user-facing setting on request ("请你允许设置/切换…"): after style switching, next wants island placement switchable between screen top and bottom, and spells out the concrete expected behavior of each mode (bottom mode embeds in the taskbar, slides over, queue grows upward) rather than accepting a bare toggle. Confidence: 0.5
- Expects visual uniformity/alignment across repeated UI elements rather than per-element sizing: reports mismatched sizes emphatically ("每张卡片的大小都不一样！！你应该同一这个行为") and wants the host to normalize them (e.g., cards in a stack forced to one shared width/height). Confidence: 0.55
- Expects alignment to propagate to inner content and to the growth direction: when a component is placed at the left/right edge, its popups must be left/right-aligned to that same side and expand only away from the edge — center-alignment makes wider content grow symmetrically and overflow off-screen ("弹出的消息应该左对齐/右对齐，中间对齐会导致溢出"). Confidence: 0.6
- Wants the widget to occupy space in the host shell's native layout rather than float as an overlay on top of it — overlapping the existing UI (e.g., the taskbar's own icons) is treated as a defect, so prefer placements that avoid occlusion or that integrate with the shell. Confidence: 0.55
- Expects element size to be uniform across contexts/position modes and never a function of where the element sits — but does not accept deleting a requested behavior to achieve that. An early revision narrowed the compact width only inside the taskbar ("嵌在任务栏变窄、出去又变宽"), which they called weird ("尺寸只由内容决定"); when the agent responded by removing the narrowing altogether, they rejected that too ("为什么…嵌入的时候也没有缩小啊！！！！"). The wanted fix is a single, context-independent size cap applied in every position mode — not removal of the requested behavior. Any size constraint must be a fixed constant, not derived from the current placement. Confidence: 0.7
- Prefers the real integrated implementation over the pragmatic workaround even when it means an invasive, large-scope, not-guaranteed-to-succeed project: when offered a zero-risk route (have the user free up taskbar space via OS settings) against a native explorer-hook injection explicitly labeled "大工程/不保证成功", they took the injection. Don't default them to the easy concession when genuine integration requires invasive work. Confidence: 0.55
- Requires system-invasive changes to be fail-safe and reversible: before approving anything that hooks or alters another process (e.g., injecting a DLL into explorer.exe) they demanded 失败自动回滚 — on any failure the change must undo itself and fall back to the previously working behavior rather than leaving the system/shell in a broken state. Confidence: 0.5
