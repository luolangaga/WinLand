# 设备插拔岛（device-island）

插 U 盘、耳机、手柄时，灵动岛上自动冒一条提示；展开就是当前所有设备的列表，每台都能**打开**，磁盘还能**安全弹出**。

## 功能

- **插上就冒出来**：设备接入 / 移除时，岛上弹一条提示（标题 + 设备名 + 盘符/容量等信息），几秒后自动收回常驻内容。
- **展开逐台操作**：鼠标悬浮岛体展开，最多 3 行；每行有「打开」；磁盘多一个「弹出」。
- **点岛体开大卡片**：完整列出当前所有设备，不受 3 行限制。
- **一台设备一个条目**：插两个 U 盘就是两个独立条目，各自打开 / 各自弹出。
- **蓝牙设备显示电量**：蓝牙耳机等设备旁边标一个小电池 + 百分比（如 `100%`）。读得到才显示，读不到不显示 —— 从不猜。

### 各类设备的动作

| 设备 | 「打开」打开什么 | 「弹出」 | 电量 |
|------|------------------|----------|------|
| U 盘 / 移动硬盘 / 存储卡 | 资源管理器定位到该盘 | ✅ 锁卷 → 卸载 → 弹出 | — |
| 耳机（USB / 蓝牙） | Windows「声音」面板（`mmsys.cpl`） | — | 蓝牙的有（设备上报过就有） |
| 耳机（3.5mm 耳机口） | Windows「声音」面板（`mmsys.cpl`） | — | — |
| 游戏手柄 | 「游戏控制器」面板（`joy.cpl`） | — | — |

## 检测方式（零第三方依赖）

全部用 Windows 自带能力，不需要任何额外的包或驱动：

| 设备 | 怎么发现 |
|------|----------|
| 磁盘 | 枚举驱动器后用 `IOCTL_STORAGE_QUERY_PROPERTY` 读**总线类型**，只保留「总线 = USB」或「系统标记为可移动」的盘 —— 内部固定盘会被排除，USB 移动硬盘（系统常报 Fixed）也能认出来 |
| 耳机 | Core Audio（MMDevice）枚举输出端点，按「枚举器总线 + 物理形态 + 设备状态」三把尺子筛，**只认插着的外接耳机**：虚拟声卡（网易、Nahimic、VB-Audio…）和板载扬声器一律不算 |
| 手柄 | `Windows.Gaming.Input.RawGameController` 的 `Added` / `Removed` 事件 |

### 为什么耳机要这么挑

先前用 `DeviceInformation.CreateWatcher(DeviceClass.AudioRender)`，它只按「是不是活动的输出端点」筛，
于是**虚拟声卡**和**板载扬声器**会被一起报出来 —— 那些根本不是用户插进来的东西。现在改成：

| 设备树上的物理总线（顺父链看） | 判定 |
|---|---|
| `ROOT` / `SWD`（虚拟、软件音频设备） | 不算 |
| 蓝牙 / USB | 算（外接总线本身就是「插进来的」；不少 USB 耳机把形态报成扬声器，再卡形态会漏真耳机） |
| `INTELAUDIO` / `HDAUDIO`（板载声卡） | 只有**耳机形态**才算，扬声器口 / HDMI / SPDIF 一律排除 |
| 设备状态 | 必须 `ACTIVE` —— 3.5mm 耳机口没插东西时系统正是标成 `UNPLUGGED` |

副标题上的连接方式（蓝牙 / USB / 3.5mm）也以**设备树**为准，不是端点自报的枚举器 ——
实测一副蓝牙耳机的枚举器会谎报 `INTELAUDIO`，只看枚举器会说成「3.5mm 耳机口」。

磁盘部分由两路共同触发：**设备变更广播窗口**（隐藏的 message-only 窗口收 `WM_DEVICECHANGE`，插拔即时响应）+ **1.2 秒轮询兜底**（防止个别虚拟盘漏事件）。

## 蓝牙电量

电量来自 PnP 设备节点上的属性集 `{104EA319-6EE2-4701-BD47-8DDBF425BBE5}`
（`DEVPKEY_Bluetooth_BatteryLevel` 家族）的 `pid 2`。「设置 → 蓝牙」显示的就是同一份 —— 由设备主动上报、Windows 缓存下来的值。

匹配方式：同一台设备在设备树里的各个节点实例 ID 里都带着**同一个 12 位十六进制蓝牙地址**
（如 `80BF21CA057B`），所以走「音频端点 → 顺父链找到蓝牙祖先 → 取地址 → 查电量表」可以**精确匹配**，不必按设备名做模糊猜测。

没有走 WinRT 的 GATT（`0x180F` 电池服务）：实测设备未连接时 `BluetoothLEDevice.FromIdAsync` 直接返回 `null`，GATT 到不了；
而且只有支持标准电池服务的设备才读得到。PnP 属性这条路更短、更稳，且零第三方依赖。

## 设置

- 在灵动岛上显示
- 岛上优先级（0–200）
- 插入时提示 / 移除时提示
- 提示显示秒数（1–15 秒）
- 分别开关：监听 U 盘 / 耳机 / 手柄

## 在岛上的位置（优先级）

宿主**同时最多只渲染 10 条活动**（主岛 1 条 + 展开队列 9 张卡：每列 3 张、最多 3 列，
`IslandWindow.MaxQueueCards`；一列放满就换到右边一列），按优先级从大到小取前 10 ——
**排到第 11 名及以后的插件既不显示、也不报错，展开也看不到**。

本机常驻插件的实测档位：媒体 100（播放时）/ 剪贴板 55 / 电池 50 / 天气 40。所以本插件默认取 **45**，
刚好高过天气，稳进常驻插件那一档。

要调优先级有两条路：

1. 本插件设置页的「岛上优先级」；
2. 宿主 **设置 → 插件管理 → 设备插拔岛 → 优先级**（写宿主键 `plugin.device-island.priority`，**覆盖**上面那个值，改完立即重排，不用重启）。

> 另外注意：插入时的**提示**走 `ShowMessage`，它是**抢占式、不受优先级影响**的 ——
> 「那一刻弹过提示」不代表「常驻卡片也能显示」，这两条路要分开判断。

## 关于「一个设备一个岛」

当前插件 SDK 里，一个插件只能注册**一条**活动岛（宿主 `IslandWindow.SetLive` 按 `owner = 插件 id` 去重）。
所以这里实现为「**一条岛 + 展开逐行列出**」：每台设备仍是独立条目、独立动作、独立状态，
但共用同一个岛体。要做到「插两个 U 盘就出现两个岛」，需要宿主侧扩展 SDK 支持一个插件注册多条活动。

## 已知边界

- 3.5mm 耳机是否会产生一个**新的**音频端点，取决于声卡驱动：有些驱动插上耳机只是「切换到耳机」而不新增端点，这种情况不会触发提示（Windows 层面没有可观测的设备变化）。
- 「弹出」对不支持弹出指令的设备（部分 USB 移动硬盘）会失败，这类设备按系统提示直接拔即可。
- 设备正在被占用（有文件打开）时，「弹出」会失败并给出原因，这是**故意的** —— 比强行解除挂载安全。
- **电量只有设备上报过才有**。蓝牙鼠标 / 键盘这类走标准 HID 或 BLE 电池服务的设备通常有；不少 TWS 耳机只用一个厂商私有 BLE 服务，系统里压根没有电量属性 —— 这类就**不显示**，不会填个假数字。
- 电量是**系统缓存值**，不是实时读数：设备主动上报时才会更新（界面上显示的其实是它最后一次上报的值）。
