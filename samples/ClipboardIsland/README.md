# 剪贴板岛（clipboard-island）

给 WinIsland 灵动岛用的剪贴板历史插件：**复制文字或图片时岛上弹一下提示，展开就是最近几条历史，点一条直接粘回你正在输入的窗口。**

## 怎么用

| 位置 | 看到什么 |
|------|----------|
| 小岛（常驻） | 剪贴板图标 + 最近一条内容的摘要 + 总条数；最新一条是图片时直接显示缩略图 |
| 复制新内容时 | 岛临时变成一条「已复制 · 摘要」通知，几秒后自动还原成常驻内容 |
| 鼠标悬浮展开 | 最近 3 条历史 —— **点其中一条，直接粘进你正在输入的那个窗口**（岛上闪一条「已粘贴 · 摘要」） |
| 点击岛体空白处 | 弹出「超级展开」大卡片：完整历史列表，点任意一条同样是「复制 + 粘贴」，右上角可以清空历史 |

「直接粘贴」是模拟一次 `Ctrl+V`。岛窗和聚光卡都是 `WS_EX_NOACTIVATE`，点它们不会抢走焦点，
所以粘贴目标就是**你点历史那一刻正在打字的那个窗口** —— 不用先切窗口再切回来。

## 设置

- **在灵动岛上显示**：关掉后不占岛，但历史照常记录。
- **复制后在岛上弹提示**：默认开。关掉后退化成「只在常驻小岛上高亮闪一下」，不打断岛上的其他内容。
- **复制后的提示显示几秒**：1 / 2 / 3 / 5 / 8 秒，默认 3 秒。对通知和高亮两种模式都生效。
- **点历史条目直接粘贴**：默认开。关掉后只把内容写回剪贴板，粘贴键自己按。
- **记录图片**：关掉后只记文字（已经记下的图片缓存可以点「清空历史」删掉）。
- **最多保留几条**：10 / 20 / 50 / 100，默认 20。超过上限的老记录会连同图片缓存一起清掉。
- **试一下提示效果**：不用真的去复制，直接预览当前模式下的提示。

## 数据存在哪

```
%LocalAppData%\WinIsland\clipboard-island\
  history.json          文字内容 + 图片的文件名 / 大小 / 时间
  images\<id>.png       图片缓存（用于缩略图和重新复制）
```

- 关掉 WinIsland 再打开，历史还在；上限之外的老记录自动清理。
- 插件只在系统剪贴板内容变化时读一次内容，**不联网、不上传任何数据**。

## 说明

- 处理**文本**、**图片**、**文件/文件夹**三类剪贴板内容。复制文件（资源管理器里 Ctrl+C）记的是一条
  **文件记录**：只存路径引用、不复制文件本身；点它写回剪贴板的也是**文件本身**
  （Win32 `CF_HDROP` + 「复制」效果，和资源管理器自己复制文件时写的是同一套），
  所以在资源管理器里粘回去就是复制文件、在收文件的程序里也是收文件。
  刻意**不附带路径文本**：带上的话，优先认文本的程序（聊天窗口之类）会粘出一串路径。
  走 `CF_HDROP` 还顺带绕开了 WinRT `StorageFile` 打不开**隐藏/系统属性**文件的问题（桌面上的 `.lnk` 经常带这些属性）。
  只有剪贴板被别的程序占着写不进去时，才退回路径文本（日志里会写明）。
- 其它格式（HTML 片段、自定义格式…）不记录，但会在日志里写明「暂不支持记录的格式 + 实际可用的格式」，方便排查。
- 判定顺序是**文件 → 文本 → 图片**：复制文件时剪贴板里通常只有文件，极少与文本/图片同时出现。
- 文本优先于图片：从 Word / Excel / 浏览器复制时，剪贴板里往往同时有文本和图片，这时记的是文本。
- 剪贴板有时会被源程序短暂占用（`CLIPBRD_E_CANT_OPEN`），插件会自动重试几次再放弃。
- 内容完全相同的一条不会重复记录，只会被提到最前 —— **但岛上照样会弹一次提示**，
  因为用户按了 `Ctrl+C` 就该有反馈；只有「我们自己写回剪贴板」引起的那一次会被静默掉。
- **粘贴不生效的情况**：目标程序以管理员身份运行时，Windows 的 UIPI 会拦下模拟按键
  （日志里会写「发送 Ctrl+V 失败」）。这时插件只把内容写回剪贴板，自己按 `Ctrl+V` 即可。
  另外目标窗口最小化、或者根本找不到可粘贴的窗口时，同样只复制不粘贴。

## 剪贴板监听为什么要两条通道

只订阅 WinRT 的 `Clipboard.ContentChanged` 会出现"**偶尔复制了却没反应**"：

- 极短时间内连续复制，事件会被合并甚至丢掉；
- 以延迟渲染方式写剪贴板的程序、走老 OLE 路径的程序，不一定触发这个事件；
- 剪贴板被某个程序短暂独占（打开了没关）时，那一次变化也会被吞掉。

所以插件并行跑两条通道，并用 Win32 `GetClipboardSequenceNumber()` 的**系统级序号**去重：

| 通道 | 作用 |
|------|------|
| `Clipboard.ContentChanged` 事件 | 正常情况下的即时响应，零延迟 |
| 400ms 定时轮询同一个序号 | 兜底：事件漏掉的任何变化，下一拍一定补上 |

序号由系统维护，剪贴板每变一次自增，**不依赖任何程序自觉上报**，所以两路合并后不会漏。
两路都先比序号再上报，谁先发现谁处理，另一路自动被吸收，也不会重复触发。

另外，读剪贴板的时机很关键：拿到变化通知后，`Clipboard.GetContent()` 必须**立刻**调用，
再排队去做解析和入库。反过来（先排队再读）会在排队期间读到更新后的内容，前一条就永久丢了。


## 从源码构建

```powershell
cd samples\ClipboardIsland
dotnet build            # 编译并自动拷贝到宿主 plugins\clipboard-island\
```

> 项目根目录的 `global.json` 把构建用的 .NET SDK 钉在 10.x，**不要删**：
> 机器上若装了更高的 SDK（如 11 预览版），不加它构建出来的插件在正式版宿主上会加载失败。

如果 WinIsland 正在运行，最后那步拷贝会失败（`MSB3027 / MSB3021`，文件被 WinIsland 锁定）。
两个办法：

1. 先退出 WinIsland 再 `dotnet build`；
2. 或者在插件目录里把旧的 `ClipboardIsland.dll` 改名（Windows 允许重命名被加载的程序集），
   再把 `bin\...\ClipboardIsland.dll` 拷进去 —— 新文件会在下次加载时生效。

构建完成后，在 WinIsland：设置 → 插件管理 → 找到「剪贴板岛」→ 点「重新加载」。
「重新加载」会先卸载旧的程序集（这个过程会把旧 dll 的占用释放掉），再按新的 `plugin.json` 加载。

日志：`%LocalAppData%\WinIsland\logs\plugin.clipboard-island.log`
